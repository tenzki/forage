# Outline structure rules (Workflowy parity)

**Status:** normative. Every rule here has a matching test in
`apps/desktop/src/editor/outlineStructure.test.ts`, named with its rule ID.

**Scope:** every operation that changes the *shape* of the outline tree — indent,
outdent, Enter, Backspace, Alt-Arrow move, drag-and-drop. Text formatting, zoom,
search, collapse toggling, and todo state are out of scope except where they
constrain a structural rule.

**Source of truth:** Workflowy's observable behavior, plus its help docs and the
2017 outdent reversion (see [Provenance](#provenance)). Where Workflowy's
behavior is undocumented and unverifiable, the rule records an explicit Forage
decision and says so.

---

## Definitions

- **Bullet** — a `listItem` node with a `nodeId`.
- **Branch / subtree** — a bullet together with all of its descendants.
- **Parent** — the bullet that owns the `bulletList` containing this bullet.
  A bullet directly in the document's root `bulletList` has no parent and is at
  **top level**.
- **Siblings** — bullets sharing the same immediate `bulletList`, in document
  order. **Previous sibling** / **following siblings** are relative to that order.
- **Visible bullet** — a bullet with no collapsed ancestor. Bullets hidden inside
  a collapsed branch are *not* visible, and never participate in
  visible-order rules. Zoom and hide-completed filters do **not** affect
  visibility for structural rules — only `collapsed` does.
- **Previous visible bullet** — the bullet immediately above in rendered order:
  the previous sibling's last visible descendant if it has one, otherwise the
  previous sibling, otherwise the parent.
- **Selection roots** — for a multi-bullet selection, the selected bullets that
  have no selected ancestor. A selected bullet whose ancestor is also selected
  moves implicitly with that ancestor and is never operated on directly.
- **System node** — a bullet with a non-null `systemRole` (`inbox`,
  `daily-notes`, `daily-note`). Governed by `systemNodeGuards.ts`.

## Invariants (INV)

These hold after *every* rule below. They are asserted once per operation family
rather than repeated in each rule's test.

| ID | Rule |
|----|------|
| INV-01 | `nodeId` is never regenerated by a structural operation. A moved bullet keeps its identity, and so does every descendant. |
| INV-02 | No empty `bulletList` node survives an operation. A parent that loses its last child loses its child list, and therefore its collapse control. |
| INV-03 | The document always contains at least one `listItem`. An operation that would empty the outline leaves a single empty bullet instead. |
| INV-04 | Each operation is exactly one undo step. One `Cmd-Z` restores the complete prior tree, including collapse state. |
| INV-05 | `collapsed` is preserved on every moved bullet and every descendant, except where a rule explicitly expands a bullet (IND-04, DRP-05). |
| INV-06 | A bullet's note (`bulletNote`), `bulletKind`, `completed`, `systemRole`, and `dailyDate` travel with it unchanged. |
| INV-07 | Relative order of untouched bullets is never altered. |
| INV-08 | An operation on a system node, or one that would move a system node out of its required position, is rejected as a whole — never partially applied. |
| INV-09 | An operation with no legal effect is a true no-op: the document is not replaced, no history entry is created, and the selection does not move. |

## IND — Indent (`Tab`)

| ID | Rule |
|----|------|
| IND-01 | A bullet with no previous sibling cannot indent. No-op (INV-09). This is the only structural reason indent fails. |
| IND-02 | The bullet becomes the **last** child of its previous sibling. Not the first — existing children keep their order and stay above it. |
| IND-03 | The bullet's whole branch moves with it. Descendant depth relative to the bullet is unchanged. |
| IND-04 | If the previous sibling is collapsed, it **expands**. The indented bullet must be visible after the operation. |
| IND-05 | Following siblings of the indented bullet are unaffected — they stay where they are, at their original depth. |
| IND-06 | The text cursor stays in the same bullet at the same character offset. |
| IND-07 | Nesting has no depth limit. |
| IND-08 | Multi-bullet selection operates on selection roots only. If **any** selection root cannot indent (IND-01), the whole operation is a no-op — relative structure between roots is never flattened. *Forage decision; Workflowy's behavior here is unverified.* |
| IND-09 | Indenting a system node is rejected (INV-08). Indenting a normal bullet *into* a system node's child list is allowed only where `systemNodeGuards` permits it. |

## OUT — Outdent (`Shift+Tab`)

| ID | Rule |
|----|------|
| OUT-01 | A top-level bullet cannot outdent. No-op (INV-09). |
| OUT-02 | The bullet becomes the next sibling of its former parent, positioned **immediately after** it. |
| OUT-03 | **Following siblings stay with the former parent.** Outdent is *logical*: it lifts one bullet and its own branch, and adopts nothing. This is the rule most implementations get wrong — see [Provenance](#provenance). |
| OUT-04 | The bullet's whole branch moves with it, unchanged. |
| OUT-05 | Preceding siblings stay with the former parent, unchanged. |
| OUT-06 | If the bullet was its parent's only child, the parent's `bulletList` is removed (INV-02) and its collapse control disappears. |
| OUT-07 | The text cursor stays in the same bullet at the same character offset. |
| OUT-08 | Outdent succeeds regardless of whether the bullet has children. There is no "has children, so refuse" case. |
| OUT-09 | Multi-bullet selection operates on selection roots only, all-or-nothing, as in IND-08. |
| OUT-10 | Outdenting a system node, or outdenting a bullet out of a system node's required subtree, is rejected (INV-08). |

## ENT — Enter

Only Enter's *structural* effects are specified here. `Shift+Enter` (note) is
covered by `bulletNote.ts` and is out of scope.

| ID | Rule |
|----|------|
| ENT-01 | Cursor at end of text, bullet has no children → new empty bullet inserted as the **next sibling**. Cursor moves into it. |
| ENT-02 | Cursor at end of text, bullet has **expanded** children → new empty bullet inserted as the **first child**. Cursor moves into it. The new bullet must appear directly below the text just typed. |
| ENT-03 | Cursor at end of text, bullet has **collapsed** children → new empty bullet inserted as the **next sibling**, and the bullet stays collapsed. Never create a bullet the user cannot see. |
| ENT-04 | Cursor at offset 0 of a **non-empty** bullet → new empty bullet inserted **before** it as a sibling. The cursor and the existing text stay in the original bullet; its children stay with it. |
| ENT-05 | Cursor mid-text → the bullet splits. Text after the cursor moves to a new **next sibling**; the original keeps the text before the cursor **and all of its children**. Cursor moves to offset 0 of the new bullet. |
| ENT-06 | Cursor at end of an **empty** bullet: ENT-01/02/03 still decide placement by children. Empty text is not itself a special case. |
| ENT-07 | A bullet created by Enter is always plain: fresh `nodeId`, `nodeType: 'user'`, `bulletKind: 'bullet'`, `completed: false`, `collapsed: false`, `systemRole: null`. Todo state and system roles are never inherited from the source bullet. |
| ENT-08 | Enter on a system node's title does not split or duplicate the system node. It creates a child of the system node (ENT-02 shape) so the outline stays usable. |
| ENT-09 | Enter with a non-empty text selection deletes the selection first, then applies the rule matching the resulting cursor position. |

## BSP — Backspace

| ID | Rule |
|----|------|
| BSP-01 | Empty bullet with **no** children, a previous visible bullet exists → the bullet is **deleted** and the cursor moves to the **end** of the previous visible bullet. Never outdented: an empty bullet's depth is not a thing Backspace edits. The previous visible bullet may be a deeper descendant of the previous sibling, or — for a first child — the **parent**. |
| BSP-02 | Empty bullet **with** children → no-op. Deleting would silently reshape a subtree. *Forage decision; Workflowy's behavior here is unverified.* |
| BSP-03 | Non-empty bullet, cursor at offset 0, bullet has no children, previous visible bullet has no children → the two bullets merge: this bullet's text appends to the previous visible bullet, this bullet is removed, and the cursor sits at the join point. |
| BSP-04 | Cursor at offset 0 of a bullet that **has** children → no-op, whether or not the bullet has text. Consistent with BSP-02. |
| BSP-05 | Cursor at offset 0 of the **first** bullet in the outline → no-op. There is nothing above to merge into. |
| BSP-06 | The last remaining bullet is never deleted. If the outline would become empty, a single empty bullet remains and keeps the cursor (INV-03). |
| BSP-07 | Backspace never deletes or merges a system node; the operation is rejected (INV-08). An empty non-system child of a system node is removable. |
| BSP-08 | Backspace with a non-empty text selection deletes the selection only. It never removes a bullet as a side effect. |

## MOV — Move up / down (`Alt+ArrowUp` / `Alt+ArrowDown`)

| ID | Rule |
|----|------|
| MOV-01 | With a previous (up) or following (down) sibling, the bullet swaps places with that sibling. Depth is unchanged; both branches stay intact. |
| MOV-02 | The bullet never descends into a sibling's children, expanded or collapsed. Workflowy "maintains its hierarchical level whenever possible", and swapping is always possible when a sibling exists. |
| MOV-03 | First child, move up → the bullet **outdents and lands immediately before its former parent**. Its following siblings stay with the former parent (same adoption rule as OUT-03). |
| MOV-04 | Last child, move down → the bullet **outdents and lands immediately after its former parent**. Its preceding siblings stay with the former parent. |
| MOV-05 | First top-level bullet, move up — or last top-level bullet, move down — is a no-op (INV-09). |
| MOV-06 | The moved bullet's whole branch travels with it, collapse states preserved (INV-05). |
| MOV-07 | The cursor stays in the moved bullet at the same offset, and the bullet is scrolled into view. |
| MOV-08 | Moving a system node is rejected (INV-08). |

## DRP — Drag and drop

Placement is decided by pointer position over the target row: top 30% →
`before`, bottom 30% → `after`, middle 40% → `inside` (`placementAt` in
`outlinerUi.ts`).

| ID | Rule |
|----|------|
| DRP-01 | `before` / `after` insert the dragged branch as a sibling of the target, at the target's depth, on the corresponding side. |
| DRP-02 | `inside` appends the dragged branch as the target's **last** child. |
| DRP-03 | Dropping a bullet onto any of its own descendants is rejected — it would detach the tree. |
| DRP-04 | Dropping a bullet onto itself is a no-op. |
| DRP-05 | An `inside` drop onto a collapsed target **expands** the target, so the dropped branch is visible. |
| DRP-06 | The source's former parent is pruned of an emptied child list (INV-02). |
| DRP-07 | The dragged branch keeps its identity and collapse state (INV-01, INV-05); the drop is one undo step (INV-04). |
| DRP-08 | Drops involving system nodes follow `systemNodeGuards` and are rejected as a whole when disallowed (INV-08). |

## Known divergences

Verified by running `outlineStructure.test.ts` against the implementation.
The BSP family was implemented on 2026-09-02 (`handleStructuralBackspace` in
`extensions.ts`) and now passes in full. 54 of 67 rules pass; the 13 below still
fail. They are listed here rather than in the rules themselves, so the rules
stay a statement of intent.

| Rule | Current Forage behavior | Cause |
|------|-------------------------|-------|
| OUT-01 | Outdenting a top-level bullet **destroys it** — it is lifted out of the `bulletList` into a bare paragraph and stops being a bullet. | `liftListItem` lifts out of the list entirely when there is no outer list. |
| OUT-03, OUT-04, OUT-08 | Following siblings are **adopted as children** of the outdented bullet. | `extensions.ts:264` calls `liftListItem`; ProseMirror's `liftToOuterList` deliberately reparents trailing siblings ("There are siblings after the lifted items, which must become children of the last item"). |
| INV-01, INV-05 on outdent | Consequences of the above: ids and collapse state end up on the wrong tree shape. | Same. |
| MOV-03, MOV-04 | No-op at sibling boundaries. | `moveBulletById` in `outlineModel.ts` indexes strictly within one sibling list. |
| MOV-07 | The caret survives the move but its offset resets to 0. | `dispatchDocument` re-seats the selection with `TextSelection.near(pos + 2)`. |
| ENT-04 | Structure is right, but the caret moves into the **new empty bullet** instead of staying with the text. | `handleTitleEnter` selects `itemPos + 2`, which is the inserted bullet. |
| ENT-09 | Enter over a text selection splits without deleting the selection first, so the selected text survives in the new bullet. | `handleTitleEnter` returns early unless `state.selection.empty`, then a later handler splits. |
| IND-04, DRP-05 | Collapsed targets are not expanded on receive, so the moved bullet lands somewhere invisible. | No expansion step in `sinkListItem` or `moveBulletTo`. |

Rules that pass, and should be protected by these tests during any further fix:
all of IND except IND-04 (including both multi-select cases), OUT-02, OUT-05,
OUT-06, OUT-07, OUT-09, ENT-01/02/03/05/06/07, all of BSP, MOV-01/02/05/06, and
all of DRP except DRP-05.

### Fixed: BSP-01 — BSP-05 (2026-09-02)

Backspace at offset 0 had no structural rule and fell through to ProseMirror's
list `joinBackward`, which only ever changed a bullet's **depth**: a first child
was outdented (and, via the same trailing-sibling adoption as OUT-03, dragged
its following siblings along as children), any other bullet was indented under
the one above, and the outline's first bullet was lifted out of the list
entirely and stopped being a bullet. `handleStructuralBackspace` now owns the
offset-0 case and swallows the key so the default cannot run.

## Provenance

- **OUT-03 (logical outdent).** Workflowy briefly shipped the opposite rule in
  2017 — outdent adopting following siblings as children, plus a "does nothing
  if not the last sibling and it has children" case. It was reverted after user
  complaints: *"We have returned Shift-Tab to its original behavior as of
  today."* ([Workflowy blog: Drag Bullets to Indent
  Them](https://blog.workflowy.com/moving-bullets-is-now-easier-than-ever/))
- **IND-02, OUT-02, branch travel.** *"Press Tab to indent a bullet and
  Shift+Tab to outdent it… When you indent a bullet, it becomes a child of the
  bullet above"*; *"Any bullets nested beneath it move with
  it."* ([Workflowy help:
  Bullets](https://workflowy.com/help/bullets.md))
- **MOV-01, MOV-02.** Move up/down *"maintains its hierarchical level whenever
  possible."* ([Workflowy help:
  Hotkeys](https://workflowy.com/help/hotkeys/))
- **ENT-01.** *"Press Enter to create a new node at the same
  level."* ([Workflowy help: Add, edit and
  format](https://workflowy.com/help/add-edit-format/))
- **IND-08, BSP-02, MOV-03, MOV-04** are Forage decisions taken where
  Workflowy's behavior could not be verified from documentation. They are
  marked as such above and are the rules most worth revisiting if a Workflowy
  comparison contradicts them.
