# Desktop settings

Settings opens on **General**, followed by **Connection**, **Agents**, **Extensions**, and **MCP servers**. Nested pages retain their parent selection. Back and Cancel return to the originating action when possible, or the parent section when an action disappeared or remains disabled. Removed accounts, agents, skills, extensions, and MCP connections return to their parent with an explanatory message.

Settings presentation is scoped in `apps/desktop/src/components/Settings/settings.css` without a cascade layer, so legacy unlayered styles cannot override the Pen-derived layout. Wide workspaces use a left-aligned 180 px navigation column, 48 px gap, and up-to-640 px content column with 40/56 px top/side padding; container queries adapt to the available workspace width rather than the whole desktop window. General uses grouped appearance rows, segmented theme buttons, Accessibility, and Support. Connection places connected accounts and paired default controls before Workspace connection. MCP inventory uses compact icon/summary/action rows; review uses one-line tool disclosures and explicit agent-choice cards.

The remaining presentation references are Diagnostics `aP053`, provider setup `KkS17`, Agents `eDZqs`, agent editing `o4cSYt`, Extensions `xttSQ`, extension details `x7roQ`/`iO4yZ`, and MCP setup `mYqK6`/`i7FjPu` in `docs/desktop.pen`. Overview groups use 36 px separation; dedicated editors use 24 px spacing without enclosing cards. Agent tools have compact source-labeled rows. Extension inventory groups have count badges; details use a generic identity icon, compact access/executor rows, and divided tools/skill/lifecycle sections. Diagnostic rows describe actual checks, not placeholder connectivity results. MCP method selection is segmented and Connect/Cancel share one action row above collapsed JSON import.

## General

**Getting started** opens or resumes the five-step local setup without replacing your outline. Existing installations enter it explicitly; paused, skipped, and completed setup do not reopen automatically. Server mode explains that guided setup is local-only. See [getting started](onboarding.md) for note editing, AI, extension, and MCP steps.

Theme supports System, Light, and Dark. System follows operating-system appearance changes while the app is open. Outline typography supports the existing default, system, serif, and monospace stacks, with Default or 12, 14, 16, 18, 20, and 24 px sizes. The static nested preview and the real outline share presentation variables; neither preference changes nor the preview create document events, undo entries, or portable agent configuration changes.

Preferences apply immediately and save automatically on this device, in `localSettingsV1` inside `settings.json`. Rapid changes serialize with account mutations and retain the latest selection. Failed persistence retains the visible preference and offers **Retry saving appearance**. Missing or unsupported preference values use compatible defaults. Preferences do not transfer to the server and remain unchanged when switching workspace modes.

The last successfully saved theme mode is mirrored in webview-local storage for synchronous startup, before the main application is imported. This disposable cache contains only System/Light/Dark, never credentials or account data. System still resolves the current OS appearance. Loading native settings reconciles any stale cache; missing, invalid, or inaccessible cache storage falls back to System. The cache is populated on the first successful settings load and does not bypass native settings or credential validation.

**Follow system motion preference** reduces nonessential animation when the operating system requests reduced motion. Focus and status feedback remain available. About uses the running Tauri build's version; the non-native development adapter explicitly labels the package version as development metadata.

### Diagnostics

General → Diagnostics provides bounded, independent workspace and runtime checks, collapsed technical details, a sanitized report, and a link to Connection. Reports contain fixed status labels and strictly admitted runtime versions only, never raw errors, credential references, tokens, paths, provider responses, or MCP configuration. Model setup reports configured account/catalog availability, not a billable model request or a live entitlement check. Local outline sync and search availability describe local operation; server checks use server readiness. Node.js is required for local agent execution, and Codex additionally for subscription image generation; server execution does not depend on desktop runtime checks.

Rows initially say **not checked**; opening Diagnostics does not probe connections. Run checks and Copy sanitized report are paired beneath the grouped results. MCP and image-generation connectivity are not independently probed or presented as verified successes.

## Connection and Agents

Connection owns the existing enrollment and provisioning flow, explicit workspace-mode switching, provider accounts/defaults, server readiness, configuration conflicts, and collapsed server connection/recovery details. Failure to read the workspace connection offers retry rather than presenting local compute as a fallback. Server execution remains authoritative until an explicit successful disconnect. See [provider connections](provider-connections.md) and [server backend](server-backend.md).

Agents retains agent/skill editing, global tools, and applicable Inbox link rules. Agent editors show read-only inherited compute with **Change in Connection**; there are no per-agent model overrides. No activity-opening or result-placement preference is exposed: existing run behavior is unchanged.

### Explicit editors

Agents and skills open dedicated application-owned editors with Save and Cancel. Leaving a dirty draft through Back, section navigation, the Settings keyboard shortcut, or a sidebar destination offers Keep editing or Discard changes. Saving disables duplicate submission and editing until persistence/publication settles. Validation and persistence failures retain the draft. A successful local save followed by failed server publication is reported explicitly; retrying the unchanged draft retries publication without creating another agent or skill. Saved changes affect subsequent admissions, not already admitted runs.

Built-in, custom, and extension tools share one ordinary allowed-tools list, with source labels and availability reasons. Syntactically valid saved references remain visible when their source disappears. Globally disabled, untrusted, incompatible, and device-local tools in server mode cannot be newly authorized from the agent picker. An unavailable saved selection may be explicitly removed; unrelated edits do not drop it. New agents start without implicit tool grants.

The agent editor follows `o4cSYt`: Name, Description, Instructions, inherited compute, and a single Tools group containing compact source-labeled rows and MCP server access. Ordinary and MCP-picker tool descriptions start collapsed and expand independently through keyboard-accessible name disclosures. Availability warnings remain visible when descriptions are collapsed; expanding a description never changes tool permissions. MCP server detail retains its one-line description previews and independent disclosures.

Edit skill uses the same field/action icons and compact source-labeled disclosure rows for Required tools, limited to the selected agent's allowlist. Descriptions start collapsed for all tool sources, including MCP. Unavailable saved requirements remain selected on unrelated saves and may be removed explicitly, but cannot be newly selected while unavailable. Extension-backed skills retain their declared configuration form and validation rather than showing LLM tool requirements.

### Agent MCP access

Each connected server shows its selected-tool count and Choose tools. There is no persisted MCP master bit or wildcard grant. First enablement opens an initially unselected review; Cancel tool review grants nothing. Use selected tools stages only those individual IDs until Save agent. Disabled global tools must first be reviewed/enabled in MCP servers. Disabling one server removes its current tool IDs from this agent's draft only, leaving the connection, global policy, other agents, and unrelated references unchanged. Changed inventories/fingerprints invalidate review and newly discovered definitions are never selected implicitly.

## Extensions

All sources use the same metadata-driven detail hierarchy: identity/status/version, Configuration, Tools, Agent access when tools exist, Use in a skill, collapsed Extension details, and lifecycle actions. Empty states distinguish absent settings, agent tools, and skill actions without an unnecessary access section for tool-free extensions. Missing/invalid manifests remain inspectable rather than switching to a bespoke error page. Trust, compatibility, configuration, and confirmed execution-environment gates remain effective when technical details are collapsed. Controls are rendered from declarations by Forage, never by loading extension UI.

Global extension-tool policy lives on the extension's detail page; agent selection lives in the ordinary agent editor, reached from Agent access. Create skill opens the shared skill editor with the generic executor preselected and a stable draft identity. The user supplies a unique valid slash label and declared per-skill configuration. Activation, installation, enablement, and cancellation create no skill. Missing required source configuration blocks creation/execution until repaired; saved unavailable executors and their configuration remain inspectable.

Extension pages do not offer Copy report. Bounded host-sanitized diagnostic text remains selectable and supports Copy diagnostics inside Extension details. Failed lifecycle/configuration operations retain actionable, secret-free UI errors rather than claiming success. General's sanitized support report remains a separate capability.

## MCP servers

The overview separates Connected from Detected on this computer, with source labels, status, enabled-tool counts, effective agent access, and one Add server action. Unchanged imported definitions are omitted from Detected; different configurations sharing a name remain distinct. Existing connections remain available when discovery is empty, partial, or fails. Scan again reads supported clients' configurations without launching commands or granting access. Every server uses the same neutral plug icon; no remote icon metadata is fetched.

Add server opens dedicated URL-first setup with Browser sign-in, Manual credentials, and None authentication drafts. Browser sign-in supports public native clients with PKCE, optional explicit registration configuration, and a five-minute system-browser request. Waiting freezes fields and offers Open browser again, Copy sign-in link, and Cancel sign-in. Failed/unsupported attempts retain the draft and require an explicit fresh retry or user-selected fallback. Manual credentials offer a Bearer token or custom Authorization header (not both); None rejects Authorization. Launch command has paired environment name/value controls and a collapsed working-directory field; the initial empty pair is not a dirty draft. JSON import is collapsed below the primary action/Cancel row. Switching methods retains separate drafts but submits only the selected method's configuration. Cancel/Back protect dirty drafts and cancel pending authorization; successful connection clears credential-bearing inputs and opens explicit review. Multiple JSON imports are reviewed individually; cancellation leaves saved connections without new grants. A failed partial import is reported rather than claiming all servers connected.

OAuth consent is not a tool grant. New connection review starts with tools/agents unchecked. Sign-in-required connections retain read-only saved selections and offer Sign in again. Every successful interactive reauthentication requires Review access/Save access before previous selections can execute, including unchanged inventories; silent refresh does not reset grants or tool IDs. Cancelling review keeps the connection but never activates post-reauthentication permissions. See [MCP browser sign-in and limitations](mcp.md#browser-sign-in-on-this-device). Real native/browser/clipboard behavior and the Pen states (`stRd6`, `qJgcM`, `mcOhA`, `vE4Au`, `ZHz9y`, `rawFS`) remain user-performed acceptance checks.

Manage opens a server's tool/agent selection. Refresh tools is beside Tools; each bounded, untrusted plain-text description has a one-line ellipsized preview and an independent keyboard-accessible disclosure. Switches stage global policy, and selected agents receive only the selected individual tool IDs on Save access. Existing agent references and unrelated servers' permissions are retained; individual agent removals use the agent editor. Global tool policy can be saved without assigning an agent. Cancel grants nothing. Approved tools automatically use current definitions without repeated review; new tools remain unchecked. Tool-list, connection binding, availability, or signed-in-account changes invalidate an open selection, but definition-only updates preserve it. Save/publication failures retain the selection with sanitized messages and unchanged retries do not repeat successful local saves.

Persisted server mode shows operator-owned metadata only, hides device scan/add/disconnect/enable actions, and retains permission editing through the existing authorized publication path. Backend or mode-load errors offer retry without desktop fallback inventory. See [MCP setup and limits](mcp.md).

## Pending native verification

Automated component, runtime, native credential, and PostgreSQL checks do not establish visual or interactive correctness in the real Tauri app. Computer Use and alternate GUI automation are prohibited for this project. Task 6.3 remains a manual release gate, in both local and server modes:

- Compare the referenced Pen screens at ordinary and narrow window widths, including long descriptions, light/dark contrast, keyboard activation, dirty exits, and focus return.
- Change theme, outline typography, and motion preferences; restart the native app and confirm persistence without document events or portable configuration writes.
- Exercise provider connection success/failure/cancel, explicit default changes, disconnect repair, and unavailable/older-server capability errors without exposing secrets or falling back locally.
- Save/cancel agents and skills while a run is admitted; confirm saved changes affect only subsequent runs. Create extension skills explicitly, including missing configuration and cancellation.
- Connect/review MCP URL, command, JSON, and detected candidates; confirm cancellation grants nothing, existing references remain, and changed fingerprints require renewed review. Verify operator-owned server inventory and sanitized failures without desktop fallback.

Live provider entitlement checks additionally require appropriate operator-owned credentials; no paid model request was performed by integrated automation. Design reconciliation remains pending for the default-compute explanation on `UVrNy` (no agent overrides), agent-access explanation on `SOQOK` (additive grants, not exclusive access), extension agent access (ordinary guarded editor rather than instant grants), and Diagnostics (actual independent checks rather than unimplemented MCP/image-generation probes). Command setup retains the real execution/download warning rather than claiming unsupported auto-start behavior.
