# ADR-0013: Embed the Pi SDK in a Local Node.js Sidecar

- **Status:** Accepted
- **Date:** 2026-09-04
- **Deciders:** Forage maintainers
- **Supersedes:** ADR-0008
- **Superseded by:** None

## Context

ADR-0008 moved agent execution out of the webview into a `pi --mode rpc` subprocess. That established the right process boundary, but made Forage depend on the behavior, installation, and version of a separate Pi CLI. It also constrained how precisely the application could construct sessions, load resources, authorize tools, retain no session history, and authenticate models.

Forage needs a local agent runtime that:

- keeps arbitrary agent and tool execution outside the Tauri webview;
- uses the Pi agent loop without depending on the Pi CLI protocol;
- accepts only application-selected instructions, context, models, and tools;
- streams bounded lifecycle events and structured outline output;
- supports cancellation and deterministic process cleanup;
- works with either an OpenAI API key or a short-lived ChatGPT OAuth credential;
- remains distinct from the portable runtime used by the optional server executor.

## Decision

We will **embed the Pi SDK in a local Node.js sidecar launched by the TypeScript frontend through a scoped Tauri shell capability**.

The sidecar owns Pi session construction, the model call and tool loop, tool execution, cancellation, and conversion of Pi lifecycle events to the application's bounded JSONL vocabulary. It communicates only through newline-delimited JSON over standard input and output. The frontend owns invocation context, agent and skill selection, effective tool policy, activity presentation, and application of validated structured results to the ProseMirror document.

Each invocation uses an in-memory Pi session. The sidecar disables automatic `AGENTS.md` loading and Pi's default tools, then supplies only Forage's explicitly constructed prompt, resources, and tool set. The application intersects globally enabled tools with the selected agent and skill policy before sending the run; the sidecar validates and bounds the payload again.

The sidecar receives the selected model credential through its child-process environment, never through process arguments or model context. It constructs an in-memory authenticated model runtime and does not persist the credential. Subscription image generation remains a separate short-lived Codex app-server flow governed by ADR-0009; API-key image generation uses the public Images API. Generated bytes are validated and converted to content-addressed assets before becoming document references.

The local sidecar protocol is an application boundary, not the public synchronization or server-agent protocol. Shared `@forage/agent-runtime` contracts define agent configuration, run input, activity, and structured results used across the desktop and server, while the sidecar adapter remains specific to local Pi execution.

## Consequences

### Positive

- Forage pins and configures the Pi SDK directly instead of depending on a separately installed Pi CLI.
- Agent code and tools remain isolated from the webview by a process boundary.
- The application retains explicit control over context, tool authorization, structured output, and cancellation.
- In-memory sessions avoid coupling the outline to Pi session persistence.
- JSONL keeps the process protocol observable, bounded, and straightforward to test.

### Negative

- Development and current packaging require a compatible Node.js runtime plus the sidecar's installed and locked dependencies.
- The TypeScript sidecar currently runs through `tsx`, increasing production packaging and startup obligations.
- Forage owns process startup, framing, output limits, stderr capture, unexpected-exit handling, and cleanup.
- Local execution through Pi and server execution through the portable agent runtime are separate adapters that must continue to honor shared contracts.
- Dependency upgrades can change Pi SDK behavior and require compatibility testing.

## Security Boundary

- Tauri permits only the configured Node command and bounded sidecar entry-point arguments.
- Input payload size, context size, instruction length, tool count, URL shape, output size, and generated image bytes are bounded and validated.
- Built-in Pi tools and automatic repository instruction discovery are disabled.
- Only explicitly enabled built-in Forage tools and validated custom HTTPS tools are constructed for a run.
- Credentials are excluded from command arguments, prompts, tool definitions, stdout events, and persisted Pi sessions.
- Malformed or oversized child output is rejected, and cancellation or application cleanup terminates the child.
- The Codex subscription-image subprocess retains the isolation controls documented in ADR-0009.

## Implementation Notes

- `apps/desktop/src/agent/piSdkClient.ts` owns scoped Tauri process startup, JSONL framing, output bounds, cancellation, and cleanup.
- `apps/desktop/src/agent/piGeneration.ts` adapts desktop invocations and sidecar events to editor generation callbacks.
- `apps/desktop/src/agent/piLocalRunner.ts` adapts the shared run contract to local Pi execution.
- `apps/desktop/src-tauri/resources/pi/sidecar/index.ts` constructs in-memory Pi sessions and the authorized tool set.
- `apps/desktop/src-tauri/resources/pi/sidecar/runtime-auth.ts` constructs the in-memory authenticated model runtime.
- `apps/desktop/src-tauri/resources/pi/sidecar/tools.ts` validates and implements local tools and structured output.
- `apps/desktop/src-tauri/capabilities/default.json` scopes the permitted Node and Codex commands.
- `packages/agent-runtime/src/contracts.ts` defines portable configuration, run, activity, and result contracts.

Production distribution must bundle or otherwise provision pinned Node, sidecar, and Codex runtimes and verify their signatures and startup behavior. The current source-plus-`tsx` development arrangement is not itself a completed distribution design.

## Validation

- The client waits for an explicit ready event and reports startup, malformed-output, timeout, and unexpected-exit failures.
- Run and abort commands are newline-delimited JSON; partial stdout chunks are reassembled before parsing.
- Sidecar input and output limits reject oversized messages.
- Only the effective authorized tool set is exposed to a Pi session.
- Automatic repository instructions and default Pi tools are absent from the session.
- API-key and ChatGPT OAuth modes create the intended in-memory model runtime without putting secrets in arguments or context.
- Structured output is validated before insertion and one editor undo removes an inserted result branch.
- Cancellation aborts the active session and process cleanup stops the child.
- Runtime probes produce actionable diagnostics when Node or Codex is unavailable.
