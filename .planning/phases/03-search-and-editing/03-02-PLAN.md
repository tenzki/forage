  <action>
    1. Create `src-tauri/src/commands/undo.rs` with these IPC commands (all with `#[tauri::command]` + `#[specta::specta]`):

       a) `record_undo_step(state, operation: String, node_id: String, before_json: String, after_json: String, group_key: Option<String>) -> Result<(), AppError>`:
          - First, delete all undo_history entries WHERE id > (SELECT position FROM undo_pointer WHERE id = 1). This clears any redo entries after the current pointer (standard undo behavior: new action invalidates redo stack).
          - INSERT into undo_history (operation, node_id, before_json, after_json, group_key).
          - UPDATE undo_pointer SET position = last_insert_rowid() WHERE id = 1.

       b) `undo_step(state) -> Result<Option<UndoResult>, AppError>`:
          - Read current position from undo_pointer.
          - If position = 0, return None (nothing to undo).
          - SELECT from undo_history WHERE id = position. Get node_id, before_json, group_key.
          - If group_key IS NOT NULL, find ALL entries with same group_key, process them all (apply each before_json).
          - For each entry: parse before_json as Node, apply it to the nodes table via UPDATE (set content, content_text, parent_id, position, collapsed, node_type, metadata). For 'delete' operations, before_json represents the deleted node — INSERT it back. For 'create' operations, before_json is empty — DELETE the node.
          - Update undo_pointer.position to the id BEFORE the group (min_id - 1, or 0 if no earlier entry).
          - Return UndoResult { node_ids: Vec<String>, operation: String } so frontend knows which nodes to reload.
          - UndoResult is a new struct with #[derive(Serialize, specta::Type)].

       c) `redo_step(state) -> Result<Option<UndoResult>, AppError>`:
          - Read current position from undo_pointer.
          - SELECT from undo_history WHERE id > position ORDER BY id ASC LIMIT 1 (or all with same group_key).
          - If no entries, return None (nothing to redo).
          - Apply after_json to nodes table (same logic as undo but using after_json).
          - Update undo_pointer.position to the max id of the redone group.
          - Return UndoResult.

    2. Update `src-tauri/src/commands/mod.rs`: Add `pub mod undo;`

    3. Update `src-tauri/src/lib.rs`: Register `record_undo_step`, `undo_step`, `redo_step` in `collect_commands![]`

    4. Add integration tests to `db_tests.rs`:
       - `test_undo_redo_structural`: Create a node, record undo step (operation='create', before_json='{}', after_json=node snapshot), call undo_step (verifies node is deleted), call redo_step (verifies node is re-created).
       - `test_undo_redo_text_group`: Create a node, record 3 undo steps with same group_key, call undo_step once, verify all 3 are undone together.

    IMPORTANT: For 'delete' undo, the before_json contains the full node — use INSERT OR REPLACE to restore it.
    IMPORTANT: For 'create' undo, the before_json is empty — DELETE the node by node_id.
    IMPORTANT: Use runtime sqlx::query() consistently (not query! macro).
