  <action>
    1. Create migration `0002_search_and_editing.sql` with ALL Phase 3 schema additions:
       - `ALTER TABLE nodes ADD COLUMN content_text TEXT NOT NULL DEFAULT '';`
       - FTS5 virtual table: `CREATE VIRTUAL TABLE nodes_fts USING fts5(content_text, content='nodes', content_rowid='rowid');`
       - Three FTS5 sync triggers (AFTER INSERT, AFTER DELETE, AFTER UPDATE on nodes) as specified in 03-RESEARCH.md Pattern 1
       - `undo_history` table with id, operation (CHECK IN text_edit/create/delete/move/indent/outdent), node_id, before_json, after_json, group_key, created_at — as specified in 03-RESEARCH.md
       - `undo_pointer` table with id CHECK(id=1), position INTEGER DEFAULT 0, and initial INSERT
       - `node_tags` table with (node_id, tag) composite PK, foreign key to nodes(id) ON DELETE CASCADE, and index on tag

    2. Create `src-tauri/src/commands/search.rs`:
       - `search_nodes(state, query: String) -> Result<Vec<SearchResult>, AppError>`: Uses runtime `sqlx::query()` (NOT query! macro — FTS5 virtual tables are not introspectable). Formats query as `"{query}*"` for prefix matching. JOINs nodes_fts to nodes via rowid. Returns id, parent_id, node_type, and snippet via `snippet(nodes_fts, 0, '<mark>', '</mark>', '...', 20)`. ORDER BY rank, LIMIT 20. SearchResult is a new struct with #[derive(Serialize, specta::Type)].
       - `get_ancestors(state, node_id: String) -> Result<Vec<AncestorNode>, AppError>`: Walks parent_id chain up to root, returns ordered list of {id, name} pairs for breadcrumb display. AncestorNode struct with id and name fields.
       - Both commands annotated with `#[tauri::command]` and `#[specta::specta]`.

    3. Update `src-tauri/src/commands/mod.rs`: Add `pub mod search;`

    4. Update `src-tauri/src/lib.rs`: Register `search_nodes` and `get_ancestors` in `collect_commands![]`

    5. Modify `update_node` in `nodes.rs`: Add `content_text: Option<String>` parameter. When provided, include `content_text = ?N` in the dynamic SET clause. This parameter will be passed by the frontend alongside content updates.

    6. Modify `create_node` in `nodes.rs`: Accept `content_text: Option<String>` parameter (default empty string if None). Insert into the content_text column.

    7. Add to `src/store/ipc.ts`:
       - `searchNodesIpc(query: string)`: invoke('search_nodes', { query }) returning SearchResult[]
       - `getAncestorsIpc(nodeId: string)`: invoke('get_ancestors', { nodeId }) returning AncestorNode[]
       - Update `updateNodeIpc` signature to accept optional `contentText: string | null` parameter
       - Update `createNodeIpc` signature to accept optional `contentText: string | null` parameter

    8. Update `treeStore.ts` `updateContent` action: After calling `extractText(content)`, pass the extracted text as `contentText` parameter to `updateNodeIpc`. Similarly update `createNode` to pass empty string content_text.

    9. Add integration test `test_search_nodes` to `db_tests.rs`: Create 3 nodes with different content_text values, call search_nodes with a matching query, assert results contain the expected node with a snippet.

    IMPORTANT: Use runtime `sqlx::query()` for ALL FTS5 queries — the query! macro cannot introspect virtual tables.
    IMPORTANT: JOIN nodes_fts to nodes via `n.rowid = nodes_fts.rowid` (NOT n.id) — FTS5 uses INTEGER rowid.
