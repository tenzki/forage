**Migration (0001_initial_schema.sql):**

Create the nodes table exactly as specified in RESEARCH.md Pattern 4:
- `id TEXT PRIMARY KEY NOT NULL` (UUID v4)
- `parent_id TEXT REFERENCES nodes(id) ON DELETE CASCADE` (adjacency list)
- `position TEXT NOT NULL` (fractional index)
- `content TEXT NOT NULL DEFAULT '{}'` (TipTap/ProseMirror JSON)
- `node_type TEXT NOT NULL DEFAULT 'note' CHECK (node_type IN ('note','agent_response','command','chat_message'))` (strict enum per user decision)
- `collapsed INTEGER NOT NULL DEFAULT 0` (boolean)
- `skill_id TEXT` (nullable, for Phase 4)
- `metadata TEXT` (JSON: generation metadata, original prompt)
- `created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ', 'now'))`
- `updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ', 'now'))`

Indexes:
- `idx_nodes_parent_position ON nodes (parent_id, position)` — primary query: children ordered by position
- `idx_nodes_node_type ON nodes (node_type)` — Phase 3 filtering

Include `PRAGMA foreign_keys = ON;` in migration as belt-and-suspenders.
Do NOT include `PRAGMA journal_mode = WAL;` in the migration — WAL is set via SqliteConnectOptions and persists once set. Including it in migration causes issues with sqlx migrate!.

**Models (models.rs):**

Create NodeType enum with `#[derive(Debug, Clone, Serialize, Deserialize, Type)]` and an explicit `to_db_str()` method returning the exact string values: "note", "agent_response", "command", "chat_message". Also implement `from_db_str()` for reading.

Create Node struct with `#[derive(Debug, Clone, Serialize, Deserialize, Type)]` matching all SQL columns. Use `String` for id, `Option<String>` for parent_id, `String` for position, `serde_json::Value` for content, `String` for node_type (store as String in struct, convert via NodeType methods), `bool` for collapsed, `Option<String>` for skill_id, `Option<serde_json::Value>` for metadata, `String` for created_at and updated_at.

IMPORTANT: Do NOT use sqlx::FromRow derive — we will use manual `sqlx::query_as::<_, Node>()` with runtime string queries (not compile-time checked) per research recommendation (Pitfall 5). Use `sqlx::Row` trait manually or `sqlx::query()` with manual field extraction.

**Errors (errors.rs):**

Create an AppError enum with variants: `Db(String)`, `NotFound(String)`, `InvalidInput(String)`. Implement `From<sqlx::Error>` for AppError. Derive `Serialize, Type` for tauri-specta export. Implement `Display`.

**DB Setup (setup.rs):**

Follow RESEARCH.md Pattern 1 exactly:
- Resolve path via `app.path().app_data_dir()` (Tauri v2 API, NOT v1 path_resolver)
- Create directory if missing
- SqliteConnectOptions: create_if_missing(true), journal_mode(Wal), synchronous(Normal), foreign_keys(true), busy_timeout(5s), optimize_on_close(true, None)
- SqlitePoolOptions: max_connections(5)
- Run `sqlx::migrate!("./migrations")`
- Return the pool

**lib.rs:**

Wire up the setup: create AppState struct with `db: SqlitePool`, call init_db in tauri::Builder::setup using `tauri::async_runtime::block_on`. For now, register no commands in the invoke_handler (Plan 02 adds commands). Set up the tauri-specta builder with an empty commands list — just enough to generate an empty bindings file.

Module declarations: `mod db;`, `mod errors;` (commands module added in Plan 02).
