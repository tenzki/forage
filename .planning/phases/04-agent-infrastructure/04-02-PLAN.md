**src/store/settingsStore.ts**: Create a Zustand store for settings management.

Settings shape:
```typescript
interface ProviderConfig {
  apiKey: string        // the actual key (masked in UI, stored encrypted)
  enabled: boolean
}

interface Settings {
  providers: {
    anthropic: ProviderConfig
    openai: ProviderConfig
    google: ProviderConfig
  }
  defaultModel: string  // e.g., 'claude-sonnet-4-20250514', 'gpt-4o', 'gemini-2.0-flash'
}
```

Store actions:
- `loadSettings()`: Send `{ type: 'get_settings' }` via agentCommandIpc. Listen for the response on `agent-event` (one-shot listener that resolves a promise). Parse and set state.
- `saveProviderKey(provider: string, apiKey: string)`: Update local state, then send `{ type: 'save_settings', data: currentSettings }` to persist encrypted.
- `removeProviderKey(provider: string)`: Clear key, disable provider, persist.
- `setDefaultModel(model: string)`: Update default model, persist.
- `isLoaded: boolean` — tracks whether settings have been fetched from sidecar.

For the agent-event listener pattern: use `@tauri-apps/api/event`'s `listen()`. Since get_settings response comes as `{ type: 'settings', data: {...} }` on the agent-event channel, the store needs to set up a one-shot listener, send the command, wait for response, then unlisten.

Important: The response correlation pattern — since the sidecar is single-channel, add an `id` field to commands and match responses by id. Use crypto.randomUUID() for request IDs.
