  <action>
Create the `src-sidecar/` directory as a separate Node.js project.

**package.json**: name "ai-sidecar", private, type "module", main "index.ts", scripts: { "build": "tsc", "start": "node dist/index.js" }. Dependencies: `@mariozechner/pi-coding-agent`. DevDependencies: `typescript`, `@types/node`.

**tsconfig.json**: target ES2022, module NodeNext, moduleResolution NodeNext, outDir "dist", strict true, esModuleInterop true.

**keystore.ts**: Implement `encryptSettings(data: object, key: Buffer): Buffer` and `decryptSettings(encryptedBuf: Buffer, key: Buffer): object` using Node.js `crypto` built-in:
- Algorithm: aes-256-gcm
- Format: iv (12 bytes) + authTag (16 bytes) + ciphertext
- `getOrCreateEncryptionKey(appDataDir: string): Buffer` — reads `encryption.key` from appDataDir; if missing, generates 32 random bytes and writes it with restrictive permissions (0o600)
- `loadSettings(appDataDir: string): object` — reads `settings.json.enc`, decrypts; returns `{}` if file doesn't exist
- `saveSettings(appDataDir: string, data: object): void` — encrypts and writes `settings.json.enc`

**keystore.test.ts**: Unit tests for encrypt/decrypt round-trip, tampered-data rejection, missing-file returns empty object. Use Node.js built-in test runner or plain assertions (not vitest — this is a separate project).

**index.ts**: Sidecar entry point. Reads JSONL from stdin line-by-line, dispatches commands, writes JSONL responses to stdout.
- On startup: read `APP_DATA_DIR` from environment (Tauri will set this)
- Command types: `{ type: 'ping' }` -> responds `{ type: 'pong' }`, `{ type: 'get_settings' }` -> responds with settings, `{ type: 'save_settings', data: {...} }` -> saves and responds `{ type: 'settings_saved' }`, `{ type: 'prompt', ... }` -> placeholder that echoes back (full pi integration in Plan 04)
- Also handle `{ type: 'summarize', messages: [...] }` -> calls the LLM to produce a summary of the given messages and responds `{ type: 'summary', id, content: '...' }`. This is used by the frontend for context window summarization (see Plan 03). Use the same model/provider as the active prompt would use. System prompt: "Summarize the following conversation concisely, preserving key facts, decisions, and context needed for continuation."
- Split stdin on `\n` byte ONLY (not Unicode line separators — per pi RPC spec)
- Each response is a single JSON line terminated by `\n`
- Handle parse errors gracefully: respond `{ type: 'error', message: '...' }` for malformed input

**src-tauri/src/commands/agent.rs**: Create new command module with:

1. `SidecarState` struct holding `Option<CommandChild>` in a `tokio::sync::Mutex` (not std::sync — async context). Store in Tauri managed state alongside AppState.

2. `#[tauri::command] pub async fn spawn_sidecar(app: tauri::AppHandle) -> Result<(), String>`:
   - Use `app.shell().sidecar("ai-sidecar")` to create command
   - Set APP_DATA_DIR env var to `app.path().app_data_dir()`
   - Call `.spawn()` to get `(rx, child)`
   - Store child in SidecarState
   - Spawn async task that reads `rx` and for each `CommandEvent::Stdout(bytes)`, parse as UTF-8 and `app.emit("agent-event", line)` — use `tauri::Emitter` trait
   - Log `CommandEvent::Stderr` for debugging
   - Handle `CommandEvent::Terminated` — clear SidecarState

3. `#[tauri::command] pub async fn agent_command(state: tauri::State<'_, SidecarState>, command: String) -> Result<(), String>`:
   - Write `command + "\n"` to sidecar stdin via `child.write()`
   - Return error if sidecar not running

4. `#[tauri::command] pub async fn kill_sidecar(state: tauri::State<'_, SidecarState>) -> Result<(), String>`:
   - Kill the child process, clear state

5. `#[tauri::command] pub async fn save_settings(state: tauri::State<'_, SidecarState>, settings: String) -> Result<(), String>`:
   - Send `{ "type": "save_settings", "data": ... }` to sidecar via agent_command

6. `#[tauri::command] pub async fn get_settings(state: tauri::State<'_, SidecarState>) -> Result<(), String>`:
   - Send `{ "type": "get_settings" }` to sidecar via agent_command
   - NOTE: This is fire-and-forget. The `Result<(), String>` return only confirms the command was written to sidecar stdin. The actual settings data arrives asynchronously via the `agent-event` Tauri event channel. The frontend must listen for `{ type: 'settings', ... }` on `agent-event` to receive the response (see settingsStore.loadSettings in Plan 02).
